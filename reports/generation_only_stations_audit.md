# Станции только для страницы «Выработка ЭЭ»

Дата проверки: 27.10.2026.

## Поведение

- На форме создания добавлен флажок «Только для агрегации на странице „Выработка ЭЭ“».
- `Station.is_generation_only`: обязательный boolean, по умолчанию `false`. Существующие станции остаются обычными.
- После создания отмеченной станции выполняется переход на «Выработку ЭЭ», а не на карточку станции.
- Станция без оборудования входит в список и итоги выработки. Применяются существующие территориальные фильтры, фильтры имени и типа, пагинация и выбранная версия БД. Фильтры оборудования не подбирают станции без соответствующего оборудования.
- Для редакторов годовые и месячные значения доступны в строке станции. Для читателей значения остаются текстом. Название специальной станции является гиперссылкой на ее карточку.
- Автосохранение: задержка 400 мс при вводе, немедленное сохранение при `change`, зеленый контур после успеха и красный при ошибке. Ошибка не стирает ввод. Последовательная отправка изменений одной ячейки предотвращает перезапись нового значения старым запросом.
- После успешного сохранения перечитываются итоги и проверочные строки текущей страницы. Текущий ввод не заменяется округленным представлением.
- Пустое значение удаляет запись соответствующего периода; ноль сохраняется. Проверяются год текущей версии, месяц, принадлежность станции текущей версии и признак станции, конечность и допустимый диапазон числа.
- Серверная проверка прав и CSRF используются существующие, как для остальных изменений энергобалансов.

## Изоляция

`app/generation/services/station_services/generation_only_visibility.py` регистрирует политику на сессиях Flask-SQLAlchemy приложения:

1. Обычные ORM-запросы исключают специальные станции, включая запросы отдельных колонок, агрегаты, алиасы и поиск по ID.
2. Принадлежащие станциям записи тоже исключаются по FK, даже если запрос не соединяется со `Station`; учитываются также связи через агрегаты и компоненты ПГУ. Это существенно для прямых запросов `StationEnergyGeneration`, агрегатов оборудования, собственных нужд и привязок топливных групп.
3. Явное включение применяется при обработке страницы `/energy_balance/ee_generation/`, сохранении ее специальных ячеек и внутренней проверке дубликата при создании. Для карточки и ее запросов подгрузки/сохранения разрешается только конкретная станция из URL, а не все специальные станции. Контекст восстанавливается в `finally`.
4. Общий загрузчик страницы сам по себе не включает специальные станции. Поэтому отдельный экспорт и другие вызовы загрузчиков остаются в обычном режиме; отдельная сводка выработки тоже не получает исключения.
5. Ключи кэша отсортированных станций/позиций страниц и данных энергобаланса разделены по режиму видимости, включая ID открытой специальной станции. Список или карта выработки со специальными станциями не переиспользуется обычной страницей.
6. Проверка дубликата при создании учитывает оба вида станций, чтобы скрытая запись не обходила подтверждение дублирующего имени.

Просмотрены пути использования `Station` и таблицы `gs_gen_stations` в приложении: генерация и карточки оборудования, топливные выборки, экология, балансы энергии и мощности, сводки и расчеты, API обмена (`generation_stations`, `generation_machines` и связанные наборы), служебные отчеты и операции с версиями. Рабочие запросы используют общую сессию приложения; отдельные независимые SQLAlchemy-сессии используются для журнала, а не для расчета станций.

### Прямой SQL

- В поиске дублей без субъекта РФ исключены специальные станции как из кандидатов на удаление, так и из станций-получателей. Это также предотвращает перенос их выработки в обычную станцию служебной очисткой.
- В отчете дублирующих UUID специальные станции исключены из подписей, строк и количества станций. Планирование уникальности UUID продолжает учитывать занятые идентификаторы.
- SQL копирования/синхронизации версий и проверок целостности не является рабочей выборкой или энергетическим расчетом. Полные данные сохраняются для обслуживания БД. Копирование получает перечень колонок из `information_schema`, поэтому новый признак переносится вместе со станцией, а не сбрасывается в `false`.
- Журнал действий и резервные копии сохраняют технический аудит операций; они не являются каталогами станций и не используются для энергетических сумм.

## Дополнение: переключатель режима в карточке

- Справа в заголовке «Информация об электростанции» размещен переключатель. Он отображается только при `created_as_generation_only = true`; для обычных по происхождению станций отсутствует. Читателям показан недоступным для изменения.
- `created_as_generation_only` запоминает происхождение независимо от текущего режима. Миграция заполнила его для уже созданных специальных станций; создание новых сохраняет оба признака. После перевода в обычную станцию переключатель остается в ее карточке, но снимается.
- Переключатель не включен в автосохранение общей информации. Он отправляется только явно общей кнопкой «Сохранить» с маркером присутствия; отсутствие снятой галочки означает `false`. Обычное автосохранение другого поля режим не меняет.
- Пока сохранен специальный режим, в карточке выводятся только общая информация, выработка станции и журнал. Скрыты группы оборудования, агрегаты, прогнозные/специальные таблицы ГЭС/ГАЭС, выработка от собственника, потребление и КПД СНЭЭ. Фильтр лет остается доступным в блоке выработки.
- Снятие галочки сохраняется вместе с общей информацией. После перенаправления и повторной загрузки отображаются стандартные блоки. Существующие значения выработки не удаляются.
- Изменение режима проверяет права генерации и происхождение станции. При изменении очищаются существующим общим сервисом кэши всех модулей, чтобы сохраненная выработка сразу попадала в обычные расчеты. Преобразованная станция включается в обычный список и полную агрегацию даже до добавления оборудования; фильтры оборудования и ограничения мощности продолжают применяться.
- При обратном включении специального режима данные агрегатов и компонентов ПГУ тоже исключаются из прямых сумм мощностей, включая запросы без соединения со станцией.

## Исправление фильтра в JOIN с псевдонимами

В фильтре связанных записей использовался столбец SQLAlchemy Core. При `joinedload` ORM создавала псевдонимы таблиц (`gs_gen_machine_tes_types_1`, `gs_fue_machine_fuel_param_1` и другие), но условие фильтра продолжало ссылаться на исходное имя таблицы. Это приводило к ошибке PostgreSQL о неверной ссылке в FROM.

Условие теперь строится через отображенный ORM-атрибут модели. Его аннотации позволяют SQLAlchemy корректно подставлять псевдоним в ON, при этом подзапросы исключаемых ID остаются Core-запросами и не скрывают сами исключаемые записи.

- Добавлены регрессионные проверки `joinedload`, `selectinload`, ленивой загрузки, явных алиасов типов ТЭС, топливных параметров, мощностей агрегатов и компонентов ПГУ. Проверено сохранение агрегата без необязательных связанных записей при LEFT JOIN.
- Целевой прогон генерации, выработки и связанных топливных функций: **85 passed**.
- На PostgreSQL воспроизведен исходный вызов `fetch_machines_with_rowspans` для версии **37** и станций **28399, 28402, 28403, 28405, 28407, 28404, 28401**. После исправления обычный режим загружает **17 агрегатов**, режим всех версий – **19**, без ошибки SQL.
- Проверен загрузчик карточки агрегата с присоединенными топливными параметрами; исключение специальных станций из обычного каталога сохраняется. Проверочные транзакции завершены откатом без изменения пользовательских данных.

## Исправление территориальных фильтров для станции 38096

У «Тест ТЭС» указан субъект РФ **Калининградская область (2272)**, но прямая РЭС не заполнена. При построении иерархии выработки использовалась РЭС субъекта, а SQL-фильтры РЭС и типа энергосистемы требовали прямую связь. Поэтому сочетание `energy_system_type_filter=162`, `union_energy_system_filter=311`, `regional_energy_system_filter=2046`, `federal_district_filter=270` исключало станцию.

Теперь фильтры РЭС, ОЭС и типа энергосистемы используют одно правило: сначала явная РЭС станции; только при ее отсутствии – связи субъекта РФ. Явная РЭС имеет приоритет, даже если субъект связан с несколькими другими РЭС. Списки и отбор ID для полных итогов используют одинаковое правило. Ключ кэша сортировки/позиций страниц обновлен до **v9**, чтобы старый список без специальной станции не использовался повторно. Данные территориальной привязки пользователя не менялись.
