# Проверка external_code и привязок ВЭС

Дата проверки: 29.10.2026. Источник: серверная БД `msk-arm-gs01` (10.31.205.27), только чтение. Серверные данные не изменялись.

## Записи без версии

На странице проверки были только столбцы именованных версий БД. При этом в выборку попадали записи с `database_version_id IS NULL`. Например:

| Станция | ID | external_code | Версия |
|---|---:|---|---|
| Вилюйские электросети – Зап.Эл.Сети | 253 | 593ba08b-1aae-5058-842d-f2acca10dfad | NULL |
| ДЭС Нюрба | 257 | 9232b152-a54f-5b97-9cd4-2c00964fe585 | NULL |

Прочерки во всех именованных версиях не означали, что код пустой: для самой записи просто не было столбца.

Исправление в коде: отдельный столбец «Без версии» с ключом `None`, без создания фиктивной версии в БД. Он применяется к станциям, группам оборудования и агрегатам. Отсутствие legacy-записи не дает ложной подсветки расхождения у объектов, представленных во всех именованных версиях. Присутствующий, но отличающийся legacy-код по-прежнему считается расхождением. Подсказки у прочерков объясняют отсутствие записи.

В версиях 22, 39, 40 и 41 соответствие UUID и ГТП такое же, как в рабочей версии. В версии 22 все три агрегата находятся на одной станции 8071. В версии 46 эти три агрегата соответствуют данным ТОПЛИВО.

Все указанные станции относятся к Пензенской области; `ref_uuid` субъекта одинаковый. Однако ТОПЛИВО использует РЭС «не указано», а рабочие станции – «ЭС Пензенской области». Равенство субъекта и названия «ВЭС» не доказывает равенство объектов.

### Контроль четвертого ГТП

Дополнительно проверен UUID `0d2d1dab-9641-5624-99ea-fbc412b18853`: агрегат 23411 в ТОПЛИВО называется `GVIE3416`, а агрегат 63452 в рабочей – `GVIE3414`. Таким образом, расхождение охватывает весь набор четырех ГТП GVIE3414–GVIE3417, а не только три строки, замеченные при копировании ДЗ.

### Мощности и связанные данные

Для UUID `5d8eedf4-e62a-4ca5-81f4-d707fb54c8cb` мощность `p_ust` на 2031 год равна 62.3 МВт в ТОПЛИВО и 62.5 МВт в рабочей. Для UUID `0819acca-716d-46e7-8bf9-67ffedaaf3f5` – 62.5 и 62.278 МВт соответственно. У агрегатов есть годовые мощности, названия и топливные параметры; у части есть привязки к группам оборудования. Простая замена `id_station` не устраняет противоречия в бизнес-идентичности.

## Решение по безопасности

Автоматическая перепривязка не выполнялась. Нельзя достоверно выбрать эталон бизнес-идентичности только по совпадению UUID или названия «ВЭС».

В скрипт копирования добавлена проверка: если существующий агрегат с тем же UUID уже относится к другой станции, возникает явная ошибка с ID источника, целевого агрегата, фактической и ожидаемой станции. Существующая обработка ошибок откатывает изменения текущей целевой версии. Скрипт не создает второй агрегат с тем же кодом и не переносит существующий молча.

Для исправления исторических данных нужно сначала подтвердить соответствие каждого ГТП GVIE3414–GVIE3417 реальному проекту и его эталонному UUID станции/агрегата. Затем можно подготовить адресную транзакцию с сохранением годовых данных и связей групп оборудования. Переименование либо перенос только трех агрегатов сейчас может ошибочно объединить разные проекты.

## Материалы проверки

- `ves_before.json` – снимки 21 агрегата (3 UUID в 7 версиях), родительских станций, субъектов и РЭС.
- `ves_related_before.json` – годовые мощности, названия и топливные параметры агрегатов GVIE3414–GVIE3417.
- `ves_bindings.sql` – запрос для повторной проверки в транзакции только чтения.
- `ves_bindings.json` – результат запроса: 27 строк по четырем UUID, включая контрольный ГТП.
- `copy_guard_verification.json` – проверка измененного `_copy_machine` на серверных данных через соединение PostgreSQL только чтения: отклонены все 15 конфликтов (3 агрегата в версиях 22, 37, 39, 40, 41), подтверждены 3 совпадающие привязки в версии 46. Изменений сессии нет.
