# Очистка неверсионных данных генерации и топлива

Дата: 29.10.2026. Цель: сервер `msk-arm-gs01` / `10.31.205.27`, БД `gs_gen`.

Пользователь выбрал удаление станций, агрегатов и групп оборудования без версии вместе с зависимыми данными, с сохранением именованных версий и общих справочников.

Состояние: безопасный план выполнен на сервере, транзакция успешно зафиксирована (COMMITTED). Удалено 101186 строк в 19 таблицах, включая 1097 станций, 161 агрегат и 584 группы оборудования. Проверка перед COMMIT подтвердила неизменность всех сохраняемых строк 34 затрагиваемых таблиц. Окончательный результат: `applied_safe/result.json`.

## Почему часть данных защищена

В БД есть строки с заполненной `database_version_id`, ссылающиеся на неверсионные агрегаты и группы. Например:

- 302 топливных параметра ссылаются на неверсионные агрегаты; для 300 существуют соответствующие агрегаты версии ТОПЛИВО, причем у всех 300 уже есть собственные топливные параметры. Часть значений различается.
- Формулы, удельные расходы, цены и другие параметры именованных версий ссылаются на неверсионные группы. Для части групп версионного аналога нет.

Автоматическое каскадное удаление затронуло бы данные именованных версий. Поэтому сохраняется вся связанная неверсионная часть графа: необходимые родители, их параметры и связи. Не выполняются произвольная перепривязка, слияние конфликтующих значений или изменение версии записи.

Полные ID и причины защиты находятся в `plan_review_safe/plan.json` и в свежем плане `applied_safe/plan.json`. Это намеренно неполная очистка: удаление защищенного остатка требует отдельного разрешения конфликтов версионных зависимостей.

Из двух неверсионных групп Архангельской ТЭЦ запись 16963 удалена; 17068 защищена, в частности, формулой рабочей версии (строка 4253). Повторный запрос после COMMIT подтвердил: с этим UUID осталось по одной группе в каждой именованной версии и одна без версии. По одному совпадению UUID удалять защищенную запись нельзя.

## Резервные копии и проверки

- `inventory.json` – исходная инвентаризация: 158 таблиц, неверсионные строки найдены в 83. Эта общая инвентаризация не является разрешением удалить справочники, логи или данные других независимых модулей.
- `root_dependencies.json`, `named_references.json` – найденные зависимости и кандидаты на версионные аналоги.
- `predelete_backup/` – отдельная резервная копия, созданная до запуска удаления в транзакции только чтения: 19 файлов COPY CSV в gzip, 101186 строк. Заголовки, количество строк и SHA256 проверены. В манифесте также сохранены контрольные суммы сохраняемых строк 34 таблиц.
- `applied_safe/` – свежая копия из транзакции удаления, план, манифест и окончательный результат.
- `applied_safe/verification.json` – отдельная проверка после COMMIT: все удаляемые ID отсутствуют, итоговые количества совпадают, SHA256 файлов копии проверены. 33 из 34 контрольных сумм сохраняемых таблиц совпали и после завершения операции. В таблице `gs_rs_equipment_technical_characteristics` продолжалась работа пользователя: ее строки имеют свежие изменения другого оператора, эта таблица не входила в DELETE. Внутри транзакции при блокировках все 34 контрольные суммы совпали до COMMIT; внешние последующие правки не откатывались. Локальные и серверные часы расходятся, поэтому оценка времени в отчете не является точной отметкой COMMIT.

Каталоги резервных копий исключены из Git локальным `.gitignore`.

Программа `scripts/cleanup_unversioned_generation_data.py`:

1. По умолчанию работает только чтением, строит граф реальных FK и защищает связанные с именованными версиями компоненты.
2. Для применения требует точный SHA256 плана; изменившийся план отменяет удаление.
3. Блокирует изменяемые таблицы на время транзакции, не отключает ограничения и не использует TRUNCATE/CASCADE.
4. Не допускает непроверенных пользовательских DELETE-триггеров.
5. До удаления сохраняет полные строки PostgreSQL COPY CSV, проверяет заголовки, количество и SHA256.
6. Удаляет дочерние строки перед родительскими. Для таблиц с версией DELETE дополнительно ограничен условием `database_version_id IS NULL`.
7. Перед COMMIT проверяет количество удаленных строк, остаток защищенных объектов и контрольные суммы всех сохраняемых строк 34 таблиц. Любая ошибка откатывает всю транзакцию.

Для восстановления предназначены файлы COPY CSV в gzip. `backup_manifest.json` содержит список колонок и `restore_order` (родители перед потомками). Восстановление нужно выполнять отдельной транзакцией, после проверки SHA256 и отсутствия конфликтов ID; последовательности при очистке не сбрасываются. Резервные копии содержат рабочие данные, их нельзя публиковать в репозитории общего доступа.
