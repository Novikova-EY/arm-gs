# Версионирование агрегатов в таблице station_details

## 🎯 Проблема

На странице `station_details` в таблице агрегатов можно редактировать:
- **Собственник** (`id_gen_company`)
- **Топливо по СО ЕЭС** (`fuel_so`)
- **Примечание** (`note`)

При изменении этих полей версия агрегата (`Machine.version`) не увеличивалась, что позволяло параллельным изменениям перезаписывать друг друга.

### Проблемный сценарий:

```
Пользователь А: открывает station_details (все агрегаты с version=1)
Пользователь Б: открывает ту же station_details (все агрегаты с version=1)

Пользователь А: изменяет собственника агрегата №3 → "ПАО Энерго"
                Сохраняет → Machine.version остаётся = 1  ❌

Пользователь Б: изменяет топливо агрегата №3 → "Газ"
                Проверка: version 1 == 1  ✅ Ошибочно пропускает!
                Сохраняет → Изменение собственника ПОТЕРЯНО  ❌
```

---

## ✅ Решение

### 1. **Добавлено скрытое поле version для каждого агрегата**

**Файл:** `app/templates/generation/stations/_machines_tbody.html`

```html
{% for machine in station.machines %}
    {# Скрытое поле version для защиты от concurrent updates #}
    {% if machine.version is defined %}
    <input type="hidden" name="machine_version_{{ machine.id }}" value="{{ machine.version }}">
    {% endif %}
    
    <!-- остальные поля агрегата -->
{% endfor %}
```

### 2. **Добавлена проверка версии в функции обновления**

**Файл:** `app/generation/services/station_services/station_services.py`

```python
def update_machines_from_form_service(user, station, form_machines, form_data):
    changes = []
    conflicts = []  # Список конфликтов версий
    
    for machine in station.machines:
        version_key = f"machine_version_{machine.id}"
        form_version = form_data.get(version_key, type=int)
        
        # Проверка версии
        if form_version and hasattr(machine, 'version') and machine.version != form_version:
            conflicts.append(f"Агрегат №{machine.machine_number}")
            log_to_db(user, f"Конфликт версий...")
            continue  # Пропускаем этот агрегат
        
        # Обновляем поля...
        if changed:
            machine.updated_at = func.now()
            flag_modified(machine, 'updated_at')
    
    # Если были конфликты, откатываем ВСЕ изменения
    if conflicts:
        flash("Обнаружены конфликты версий...", "danger")
        db.session.rollback()
        return []
    
    db.session.commit()
    return changes
```

### 3. **Обновление версии при изменении**

При изменении любого из полей (fuel_so, note, id_gen_company):

```python
if machine_changed:
    from sqlalchemy.sql import func
    from sqlalchemy.orm.attributes import flag_modified
    machine.updated_at = func.now()
    flag_modified(machine, 'updated_at')
    # → Machine.version автоматически увеличится при commit()
```

## 🔧 Как это работает

### 1. **Отправка версий в форме**
При загрузке страницы для каждого агрегата создаётся скрытое поле:
```html
<input type="hidden" name="machine_version_5" value="1">
<input type="hidden" name="machine_version_6" value="1">
<!-- и т.д. для каждого агрегата -->
```

### 2. **Проверка версий при сохранении**
Для каждого агрегата:
- Извлекается версия из формы (`form_version`)
- Сравнивается с версией в БД (`machine.version`)
- Если **НЕ совпадают** → добавляется в список конфликтов
- Агрегат с конфликтом **пропускается**

### 3. **Обработка конфликтов**
Если хотя бы один агрегат имеет конфликт версий:
- Показывается сообщение с перечислением проблемных агрегатов
- **ВСЕ** изменения откатываются (`rollback`)
- Пользователь должен обновить страницу

### 4. **Инкремент версии**
При успешном изменении:
- Обновляется `machine.updated_at`
- SQLAlchemy автоматически увеличивает `machine.version`
- Новая версия сохраняется в БД

## 💡 Важные особенности

### 1. Откат всех изменений при конфликте

Если хотя бы один агрегат имеет конфликт версий, **ВСЕ** изменения откатываются:

```python
if conflicts:
    db.session.rollback()  # Откатываем ВСЕ изменения
    return []
```

**Причина:** Пользователь мог изменить несколько агрегатов одновременно. Сохранение части изменений может привести к несогласованности данных.

### 2. Проверка версии для КАЖДОГО агрегата

Каждый агрегат проверяется отдельно:
```python
for machine in station.machines:
    form_version = form_data.get(f"machine_version_{machine.id}")
    if form_version != machine.version:
        conflicts.append(...)  # Конфликт для этого агрегата
```

### 3. Пропуск агрегатов с конфликтами

Агрегаты с конфликтами пропускаются, но их изменения не теряются:
```python
if version_conflict:
    continue  # Пропускаем, но не изменяем
```

Затем в конце всё откатывается, поэтому пользователь может обновить страницу и повторить изменения.
