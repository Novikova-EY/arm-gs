## Введение

### Что такое система версионирования?

Система версионирования базы данных позволяет:
- 📌 **Управлять множественными версиями данных** в одной базе данных
- 🔄 **Переключаться между версиями** без потери данных
- 💾 **Создавать снимки состояния** базы данных
- 📊 **Сравнивать версии** и анализировать изменения
- ⏰ **Автоматически создавать резервные копии** по расписанию

### Для кого это руководство?

- Аналитики, работающие с данными разных периодов
- Администраторы, управляющие версиями справочников
- Разработчики, тестирующие различные сценарии
- Пользователи, нуждающиеся в истории изменений данных

## Концепция версионирования

### Как это работает?

Система версионирования основана на следующих принципах:

1. **Версия БД** - это логическая метка, которая присваивается данным
2. **Активная версия** - текущая версия, с которой работают все пользователи
3. **Фильтрация данных** - автоматический показ данных только текущей версии
4. **Снимки** - физические копии данных версии (бэкапы)

### Схема работы

```
┌─────────────────────────────────────────────────────────────┐
│                     База данных                              │
│                                                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │  Версия 1    │  │  Версия 2    │  │  Версия 3    │      │
│  │  (Базовая)   │  │  (Активна)   │  │  (Будущая)   │      │
│  │              │  │     ✓        │  │              │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
│         ↓                 ↓                 ↓                │
│    Данные 2024      Данные 2025      Данные 2026            │
└─────────────────────────────────────────────────────────────┘
         ↑                 ↑                 ↑
    Пользователь видит только данные активной версии
```

### Ключевые понятия

| Термин | Описание |
|--------|----------|
| **Версия** | Логическая метка данных (например, "Версия 1.0", "Данные 2025") |
| **Номер версии** | Уникальный числовой идентификатор версии |
| **Активная версия** | Версия, данные которой отображаются всем пользователям |
| **Снимок** | Физическая копия данных версии (файл .dump) |
| **Фильтрация** | Автоматический показ данных только текущей версии |
| **database_version_id** | Поле в таблицах, связывающее запись с версией |

## Интерфейс управления версиями

### Где найти?

**Путь:** Главное меню → Станции → **Управление версиями БД**

**URL:** `/generation/stations/database_versions`

### Индикатор версии

В верхней части каждой страницы отображается индикатор текущей версии:

```
┌────────────────────────────────────────────────────┐
│ 💾 Версия БД: Версия 2.0 (v2) ✓ Активна  [Версии] │
└────────────────────────────────────────────────────┘
```

**Возможности:**
- Показывает текущую активную версию
- Клик на **[Версии]** → переход к управлению версиями
- Обновляется автоматически при смене версии

###  Главная страница версий

 Главная страница управления версиями содержит:

1. **Фильтр поиска** - поиск по названию или описанию
2. **Таблица версий** со столбцами:
   - Номер версии
   - Название
   - Описание
   - Статус (Активна/Неактивна)
   - Дата создания
   - Дата обновления
   - Снимок (есть/нет)
3. **Кнопки действий**:
   - ✅ **Установить активной** - сделать версию текущей
   - 💾 **Создать снимок** - сохранить данные версии
   - 📥 **Загрузить снимок** - восстановить данные из снимка
   - ✏️ **Редактировать** - изменить название/описание
   - 🗑️ **Удалить** - удалить версию (только неактивные)
4. **Панель инструментов**:
   - ➕ **Добавить версию**
   - 📊 **Сравнить версии**
   - 📤 **Экспорт в Excel**

## Создание версий

### ⚠️ Важно: Новые версии создаются пустыми!

Когда вы создаете новую версию, она **не содержит данных**. Все существующие данные привязаны к другим версиям через поле `database_version_id`.

**Решение:** Используйте скрипт копирования данных (см. раздел "[Копирование данных между версиями](#копирование-данных-между-версиями)" ниже).

### Создание новой версии

#### Шаг 1: Открыть форму

1. Перейти в **Управление версиями БД**
2. Нажать кнопку **➕ Добавить версию**

#### Шаг 2: Заполнить форму

**Обязательные поля:**

| Поле | Описание | Пример |
|------|----------|--------|
| **Номер версии** | Уникальный номер (целое число) | `3` |
| **Название** | Уникальное название версии | `Версия 3.0` |
| **Описание** | Подробное описание (опционально) | `Данные на 2026 год с прогнозными показателями` |

**Пример заполнения:**

```
Номер версии: 3
Название: Версия 3.0 - Прогноз 2026
Описание: Прогнозные данные по станциям и машинам на 2026 год.
          Включает планируемый ввод новых мощностей.
```

#### Шаг 3: Сохранить

- Нажать **Сохранить**
- Версия будет создана со статусом **неактивная**

### Рекомендации по именованию

**✅ Хорошие примеры:**
- `Версия 1.0 - Базовая`
- `Данные 2025`
- `Версия 2.1 - Обновление Q1`
- `Тестовая версия - Март 2025`

**❌ Плохие примеры:**
- `Версия` (слишком общее)
- `v1` (слишком короткое)
- `123` (непонятно)
- `Новая` (не информативно)

## Работа с версиями

### Активация версии

**Назначение:** Установить версию как текущую для всех пользователей

#### Как активировать:

1. Перейти в **Управление версиями БД**
2. Найти нужную версию в списке
3. Нажать кнопку **✅ Установить активной**
4. Подтвердить действие

**Результат:**
- Выбранная версия становится активной (✓)
- Предыдущая активная версия становится неактивной
- Все пользователи видят данные новой активной версии
- Индикатор в header обновляется

### Редактирование версии

**Что можно изменить:**
- ✏️ Название
- ✏️ Описание

**Что нельзя изменить:**
- ❌ Номер версии (уникальный идентификатор)
- ❌ Дата создания

#### Как редактировать:

1. Перейти в **Управление версиями БД**
2. Найти версию в таблице
3. Изменить название или описание прямо в ячейке
4. Нажать **Сохранить изменения** внизу таблицы

### Удаление версии

**⚠️ Внимание:** Удаление версии безвозвратно!

#### Ограничения:

- ❌ **Нельзя удалить активную версию**
- ❌ Нужно сначала активировать другую версию

#### Как удалить:

1. Перейти в **Управление версиями БД**
2. Убедиться, что версия **неактивна**
3. Поставить галочку в столбце **Удалить**
4. Нажать **Сохранить изменения**
5. Подтвердить удаление

**Что удаляется:**
- ✅ Запись о версии из БД
- ✅ Файл снимка (если существует)
- ✅ Связи записей с этой версией (устанавливаются в NULL)

**Что НЕ удаляется:**
- ✅ Сами данные остаются в БД
- ✅ Данные становятся доступны во всех версиях (database_version_id = NULL)

## Снимки версий

### Что такое снимок?

**Снимок версии** - это физическая копия всех данных базы данных на момент создания снимка.

**Формат:** Сжатый дамп PostgreSQL (.dump)

**Применение:**
- 💾 Резервное копирование
- 🔄 Восстановление данных
- 📤 Передача данных между серверами
- 🧪 Создание тестовых копий

### Создание снимка

#### Как создать:

1. Перейти в **Управление версиями БД**
2. Найти версию в списке
3. Нажать **💾 Создать снимок**
4. Дождаться завершения операции

**Процесс:**
```
Начало → Поиск pg_dump → Создание backup → Сохранение пути → Готово
   ↓           ↓              ↓                ↓              ↓
  0%         20%            60%              90%           100%
```

**Время создания:** 1-5 минут (зависит от объема данных)

**Расположение файла:**
```
backups/
└── versions/
    └── version_3_20251021_123615.dump
```

**Размер:** Обычно 50-200 МБ (сжатый формат)

#### Что входит в снимок:

- ✅ Все таблицы обеих схем (generation, refdata)
- ✅ Все данные всех версий
- ✅ Структура БД (таблицы, индексы, constraints)
- ✅ Последовательности (sequences)
- ❌ Не включаются: пользователи, права доступа

### Загрузка снимка

**⚠️ ВНИМАНИЕ:** Загрузка снимка **заменит все данные** в базе!

#### Меры предосторожности:

1. **Автоматический бэкап:** Перед загрузкой автоматически создается бэкап текущего состояния
2. **Местоположение:** `backups/auto_before_restore/`
3. **Восстановление:** Можно откатиться, если что-то пошло не так

#### Как загрузить:

1. Перейти в **Управление версиями БД**
2. Найти версию со снимком
3. Нажать **📥 Загрузить снимок**
4. **Подтвердить** операцию (прочитать предупреждение!)
5. Дождаться завершения

**Процесс:**
```
Автобэкап → Поиск pg_restore → Очистка БД → Восстановление → Активация
    ↓            ↓                 ↓             ↓              ↓
   10%          20%               40%           80%          100%
```

**Время загрузки:** 2-10 минут (зависит от объема)

**Результат:**
- ✅ Все данные восстановлены из снимка
- ✅ Версия автоматически активируется
- ✅ Создан автоматический бэкап старого состояния

#### В случае ошибки:

Если загрузка прошла неудачно, можно восстановить предыдущее состояние:

```bash
# 1. Найти последний автоматический бэкап
ls -lt backups/auto_before_restore/

# 2. Восстановить вручную через pg_restore
pg_restore -h localhost -U postgres -d arm_gs --clean --if-exists \
  backups/auto_before_restore/auto_backup_before_restore_20251021_123615.dump
```

## Копирование данных между версиями

### Проблема: Новая версия пустая

Когда вы создаете новую версию, она **не содержит данных**. Это нормально - новая версия это только логическая метка. Данные нужно либо создать заново, либо скопировать из существующей версии.

### Решение: Скрипт копирования

Используйте скрипт `copy_version_data.py` для копирования данных между версиями.

#### Как использовать:

**Шаг 1: Создайте новую версию**
```
Меню → Управление версиями БД → ➕ Добавить версию
Пример: Версия 7 - Данные 2026
```

**Шаг 2: Запустите скрипт**
```bash
python copy_version_data.py
```

**Шаг 3: Выберите версии**
```
Исходная версия (откуда копировать): 6
Целевая версия (куда копировать): 7
```

**Шаг 4: Подтвердите**
```
Продолжить? (да/нет): да
```

### Что копируется

Скрипт копирует все данные из следующих таблиц:
- ✅ Станции (stations)
- ✅ Мощности станций (station_power)
- ✅ Группы станций (station_groups)
- ✅ Машины (machines)
- ✅ Мощности машин (machine_power)
- ✅ Топлива машин (machine_fuels)
- ✅ Типы ТЭС машин (machine_tes_types)
- ✅ ПГУ машины (pgu_machines)
- ✅ Мощности ПГУ (pgu_machine_power)
- ✅ Котлы (boilers)
- ✅ Документы (documents)

**Не копируются:**
- ❌  Справочники (refdata) - они общие для всех версий
- ❌ История изменений (логи)
- ❌ Файлы и загрузки

### Пример использования

```
=== ДОСТУПНЫЕ ВЕРСИИ ===
[5] Версия 5: Данные 2024
[6] Версия 6: Данные 2025 ✓ АКТИВНА
[7] Версия 7: Данные 2026

=== СТАТИСТИКА ПО ДАННЫМ ===
stations          - Всего:  1211
                     Версия NULL: 1211 записей
machines          - Всего:  5423
                     Версия NULL: 5423 записей

Исходная версия: NULL
✓ Выбрана исходная версия: Данные без версии (NULL)

Целевая версия (ID): 6
✓ Выбрана целевая версия: Версия 6: Данные 2025

Продолжить? (да/нет): да

КОПИРОВАНИЕ ДАННЫХ...
✓ stations       - Скопировано:  1211 записей
✓ machines       - Скопировано:  5423 записей
...

✅ УСПЕШНО! Всего скопировано: 28547 записей
```

### Варианты копирования

**1. Копировать из конкретной версии**
```
Исходная версия: 6  (ID версии)
```

**2. Копировать данные без версии (NULL)**
```
Исходная версия: NULL
```

**3. Копировать все данные (из всех версий)**
```
Исходная версия: ALL
```

### Типичные сценарии

#### Сценарий 1: Создать версию для следующего года

```bash
# 1. Создать версию "Данные 2026" (получили ID=7)
# 2. Скопировать данные из версии 2025
python copy_version_data.py
# Исходная: 6 (Данные 2025)
# Целевая: 7 (Данные 2026)

# 3. Активировать версию 7
# 4. Внести изменения (новые станции, обновленные мощности)
# 5. Сравнить версии 6 и 7
```

#### Сценарий 2: Перенести старые данные в версию

```bash
# У вас 1211 станций с database_version_id = NULL
# Хотите их привязать к версии

# 1. Создать версию "Базовая версия" (ID=1)
# 2. Скопировать
python copy_version_data.py
# Исходная: NULL
# Целевая: 1

# 3. Теперь все данные в версии 1
```

### После копирования

1. **Активируйте** целевую версию
2. **Проверьте** данные на странице станций
3. **Внесите изменения** в данные новой версии
4. **Переключайтесь** между версиями для сравнения

### Откат копирования

Если скопировали по ошибке, можно удалить данные:

```sql
-- Удалить все данные версии 7
DELETE FROM gs_gen.stations WHERE database_version_id = 7;
DELETE FROM gs_gen.machines WHERE database_version_id = 7;
-- и т.д.
```

**Или** удалите саму версию через веб-интерфейс (это обнулит `database_version_id`, но не удалит записи).

См. **[COPY_VERSION_GUIDE.md](../COPY_VERSION_GUIDE.md)** для полного руководства по копированию данных.

## Сравнение версий

### Зачем сравнивать версии?

- 📊 Увидеть количественные изменения между версиями
- 🔍 Проанализировать, какие таблицы изменились
- 📈 Получить статистику добавленных/удаленных записей
- 📤 Экспортировать отчет в Excel

### Как сравнить версии

#### Шаг 1: Открыть форму

1. Перейти в **Управление версиями БД**
2. Нажать **📊 Сравнить версии**

**URL:** `/generation/stations/compare_versions`

#### Шаг 2: Выбрать версии

**Форма сравнения:**

```
┌─────────────────────────────────────────────────┐
│       Сравнение версий базы данных              │
├─────────────────────────────────────────────────┤
│                                                 │
│  Базовая версия (1):  [Выбрать версию ▼]       │
│                                                 │
│  Сравниваемая версия (2): [Выбрать версию ▼]   │
│                                                 │
│              [Сравнить версии]                  │
└─────────────────────────────────────────────────┘
```

**Пример:**
- Базовая версия: `Версия 1.0 - Базовая`
- Сравниваемая: `Версия 2.0 - Обновление 2025`

#### Шаг 3: Просмотреть результаты

**Результаты отображаются в виде:**

1. **Общая статистика:**
```
┌────────────────────────────────────────────┐
│  Общая статистика различий                 │
│                                            │
│  • Общая разница: +1,250 записей          │
│  • Измененных таблиц: 8 из 25             │
│  • Максимальное изменение: +500 (45.5%)   │
└────────────────────────────────────────────┘
```

2. **Детальная таблица по каждой таблице:**

| Таблица | Версия 1 | Версия 2 | Разница | Изменение |
|---------|----------|----------|---------|-----------|
| gs_gen.stations | 100 | 120 | +20 | +20.0% 🟢 |
| gs_gen.machines | 500 | 550 | +50 | +10.0% 🟢 |
| gs_gen.machine_power | 1,500 | 1,650 | +150 | +10.0% 🟢 |
| refdata.fuels | 30 | 35 | +5 | +16.7% 🟢 |
| refdata.gen_companies | 50 | 45 | -5 | -10.0% 🔴 |

**Цветовая индикация:**
- 🟢 **Зеленый** - данные добавлены
- 🔴 **Красный** - данные удалены
- ⚪ **Серый** - без изменений

#### Шаг 4: Экспорт в Excel

1. Нажать **📤 Экспорт в Excel**
2. Файл скачается автоматически
3. Имя файла: `version_comparison_1_vs_2_20251021_123615.xlsx`

**Содержимое файла:**
- Лист "Сравнение" с таблицей различий
- Форматирование с цветами
- Формулы для процентов

## Автоматические бэкапы

### Настройка

Автоматические бэкапы создаются по расписанию без участия пользователя.

#### Конфигурация

Добавьте в файл `.env`:

```bash
# Включить автоматические бэкапы
ENABLE_SCHEDULED_BACKUPS=True

# Директория для хранения (по умолчанию: backups/auto)
AUTO_BACKUP_DIR=backups/auto

# Количество хранимых бэкапов (по умолчанию: 7 - неделя)
KEEP_AUTO_BACKUPS=7

# Расписание: каждый день в 2:00 ночи
BACKUP_SCHEDULE_HOUR=2
BACKUP_SCHEDULE_MINUTE=0
```

### Расписание

**По умолчанию:** Каждый день в 02:00

**Примеры других расписаний:**

| Описание | HOUR | MINUTE |
|----------|------|--------|
| Каждый день в полдень | 12 | 0 |
| Каждый день в 23:30 | 23 | 30 |
| Каждый день в 3 утра | 3 | 0 |

### Структура бэкапов

```
backups/
├── auto/                              # Автоматические бэкапы
│   ├── auto_backup_20251021_020000.dump
│   ├── auto_backup_20251022_020000.dump
│   └── auto_backup_20251023_020000.dump
├── versions/                          # Снимки версий
│   └── version_3_20251021_123615.dump
└── auto_before_restore/               # Перед восстановлением
    └── auto_backup_before_restore_20251021_143020.dump
```

### Автоматическая очистка

**Принцип:** Оставляет только последние N бэкапов

**Настройка:** `KEEP_AUTO_BACKUPS=7` (по умолчанию)

**Логика:**
1. После каждого бэкапа проверяется количество файлов
2. Файлы сортируются по дате создания
3. Старые файлы (сверх KEEP_AUTO_BACKUPS) удаляются

**Пример:**
```
Есть 10 бэкапов → KEEP_AUTO_BACKUPS=7 → Удаляются 3 самых старых
```

### Мониторинг

#### Проверка работы бэкапов:

**1. Просмотр файлов:**
```bash

```

**2. Просмотр логов:**
```bash

```

## FAQ и решение проблем

### Часто задаваемые вопросы

#### 1. Что будет, если не создать версии?

**Ответ:** Система будет работать в режиме "все версии":
- Отображаются все данные независимо от версии
- Фильтрация по версиям не применяется
- Данные с `database_version_id = NULL` видны всегда

#### 2. Можно ли удалить активную версию?

**Ответ:** ❌ Нет. Сначала нужно:
1. Активировать другую версию
2. Затем удалить нужную

#### 3. Что произойдет при удалении версии с данными?

**Ответ:** 
- Запись о версии удаляется
- Связь данных с версией обнуляется (`database_version_id = NULL`)
- Сами данные остаются в БД
- Данные становятся доступны во всех версиях

#### 4. Как часто нужно создавать снимки?

**Рекомендации:**
- ✅ Перед массовыми изменениями
- ✅ После завершения важных работ
- ✅ Перед переключением версий
- ✅ Периодически (раз в месяц/квартал)

#### 5. Сколько места занимают снимки?

**Ответ:**
- Один снимок: 50-200 МБ (сжатый)
- 7 автоматических бэкапов: ~500-1400 МБ
- Снимки версий: ~100-300 МБ каждый

#### 6. Можно ли работать с несколькими версиями одновременно?

**Ответ:** ❌ Нет. Активна может быть только одна версия.
Все пользователи видят данные активной версии.

#### 7. Как перенести данные между серверами?

**Шаги:**
1. Создать снимок версии на исходном сервере
2. Скопировать файл .dump на целевой сервер
3. Создать версию на целевом сервере
4. Указать путь к файлу снимка вручную (в БД)
5. Загрузить снимок

#### 8. Можно ли отключить версионирование?

**Ответ:** ✅ Да. Просто не создавайте версии:
- Если нет активной версии, система показывает все данные
- Фильтрация не применяется
- Система работает в "обычном" режиме

    index=True
)

2. **Проверить service:**
```python
from app.common.services.database_version_filter import apply_version_filter

def model_query(...):
    query = Model.query.filter(...)
    
    # Должна быть эта строка
    query = apply_version_filter(query, Model)
    
    return query
```

### SQL для работы с версиями

#### Просмотр версий

```sql
-- Все версии
SELECT * FROM refdata.database_versions
ORDER BY version_number;

-- Активная версия
SELECT * FROM refdata.database_versions
WHERE is_active = true;
```

#### Статистика по версиям

```sql
-- Количество записей по версиям (для таблицы stations)
SELECT 
    COALESCE(database_version_id::text, 'NULL') AS version,
    COUNT(*) AS count
FROM gs_gen.stations
GROUP BY database_version_id
ORDER BY database_version_id;

-- Общая статистика по всем таблицам
SELECT 
    'stations' AS table_name,
    database_version_id,
    COUNT(*) AS records
FROM gs_gen.stations
GROUP BY database_version_id

UNION ALL

SELECT 
    'machines' AS table_name,
    database_version_id,
    COUNT(*) AS records
FROM gs_gen.machines
GROUP BY database_version_id

ORDER BY table_name, database_version_id;
```

#### Ручная активация версии

```sql
-- Деактивировать все версии
UPDATE refdata.database_versions
SET is_active = false;

-- Активировать версию 3
UPDATE refdata.database_versions
SET is_active = true
WHERE version_number = 3;
```

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **Активная версия** | Версия БД, данные которой отображаются всем пользователям системы |
| **Бэкап** | Резервная копия базы данных |
| **Версия БД** | Логическая метка, присваиваемая данным для их группировки |
| **Миграция** | Процесс изменения структуры базы данных |
| **Middleware** | Промежуточное ПО, которое автоматически устанавливает текущую версию |
| **Номер версии** | Уникальный числовой идентификатор версии |
| **pg_dump** | Утилита PostgreSQL для создания резервных копий |
| **pg_restore** | Утилита PostgreSQL для восстановления из резервных копий |
| **Снимок (Snapshot)** | Физическая копия данных версии в виде файла .dump |
| **Фильтрация** | Автоматический отбор данных только текущей версии |
| **database_version_id** | Поле в таблице, связывающее запись с конкретной версией |
