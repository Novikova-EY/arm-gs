# Автоматические Бэкапы Базы Данных

## Обзор

Система автоматических бэкапов позволяет создавать резервные копии базы данных по расписанию без ручного вмешательства.

## 🚀 Возможности

- ✅ Автоматическое создание бэкапов по расписанию (cron)
- ✅ Автоматическая очистка старых бэкапов
- ✅ Настраиваемое расписание через переменные окружения
- ✅ Настраиваемое количество хранимых бэкапов
- ✅ Логирование всех операций
- ✅ Использование pg_dump для создания сжатых бэкапов

## ⚙️ Настройка

### 1. Переменные окружения

Добавьте в файл `.env`:

```bash
# Включить автоматические бэкапы (по умолчанию: False)
ENABLE_SCHEDULED_BACKUPS=True

# Директория для хранения автоматических бэкапов (по умолчанию: backups/auto)
AUTO_BACKUP_DIR=backups/auto

# Количество хранимых бэкапов (по умолчанию: 7 - последняя неделя)
KEEP_AUTO_BACKUPS=7

# Расписание бэкапов (по умолчанию: каждый день в 2:00)
BACKUP_SCHEDULE_HOUR=2
BACKUP_SCHEDULE_MINUTE=0
```

### 2. Установка зависимостей

Убедитесь, что установлен `APScheduler`:

```bash
pip install APScheduler==3.10.4
```

Или из requirements.txt:

```bash
pip install -r requirements.txt
```

### 3. Требования

- PostgreSQL должен быть установлен (требуется `pg_dump`)
- Переменные окружения БД должны быть настроены:
  - `DB_HOST`
  - `DB_PORT`
  - `DB_USER`
  - `DB_PASS`
  - `DB_NAME`

## 📋 Расписание

### Формат Cron

Расписание настраивается через переменные:

- `BACKUP_SCHEDULE_HOUR` - час (0-23)
- `BACKUP_SCHEDULE_MINUTE` - минута (0-59)

### Примеры расписаний

**Каждый день в 2:00 ночи:**
```bash
BACKUP_SCHEDULE_HOUR=2
BACKUP_SCHEDULE_MINUTE=0
```

**Каждый день в полдень:**
```bash
BACKUP_SCHEDULE_HOUR=12
BACKUP_SCHEDULE_MINUTE=0
```

**Каждый день в 23:30:**
```bash
BACKUP_SCHEDULE_HOUR=23
BACKUP_SCHEDULE_MINUTE=30
```

Для более сложных расписаний (например, несколько раз в день) можно расширить `BACKUP_SCHEDULE` в `config.py`:

```python
BACKUP_SCHEDULE = {
    'hour': '*/6',  # Каждые 6 часов
    'minute': 0
}
```

## 📁 Структура бэкапов

```
backups/
├── auto/                           # Автоматические бэкапы
│   ├── auto_backup_20250121_020000.dump
│   ├── auto_backup_20250122_020000.dump
│   └── auto_backup_20250123_020000.dump
├── versions/                       # Бэкапы версий (ручные)
│   └── version_1_20250120_150000.dump
└── auto_before_restore/            # Автоматические перед восстановлением
    └── auto_backup_before_restore_20250121_100000.dump
```

## 🔧 Использование

### Автоматический режим

После включения `ENABLE_SCHEDULED_BACKUPS=True` бэкапы создаются автоматически по расписанию.

### Ручной запуск бэкапа

Для тестирования или ручного создания бэкапа:

```python
from app.common.services.scheduled_backup_service import scheduled_backup_service

# В контексте Flask
with app.app_context():
    scheduled_backup_service.run_backup_now()
```

## 📊 Логирование

Все операции бэкапов логируются:

```
[INFO] Автоматические бэкапы запущены по расписанию: {'hour': 2, 'minute': 0}
[INFO] Начало автоматического бэкапа БД
[INFO] Автоматический бэкап успешно создан: backups/auto/auto_backup_20250121_020000.dump, Размер: 125.43 МБ
[INFO] Очистка завершена. Удалено старых бэкапов: 1
```

## 🗑️ Автоматическая очистка

После каждого бэкапа автоматически удаляются старые файлы, оставляя только последние `KEEP_AUTO_BACKUPS` бэкапов (по умолчанию: 7).

### Логика очистки

1. Получить список всех файлов `auto_backup_*.dump`
2. Отсортировать по времени создания (новые первые)
3. Оставить `KEEP_AUTO_BACKUPS` самых новых
4. Удалить остальные

## ⚠️ Важные замечания

### Безопасность

- ⚠️ Файлы бэкапов содержат **все данные** БД
- ⚠️ Убедитесь, что директория `backups/` защищена от несанкционированного доступа
- ⚠️ Не храните бэкапы в публично доступных директориях
- ⚠️ Рассмотрите шифрование бэкапов для production

### Производительность

- 📌 Бэкапы могут занимать несколько минут для больших БД
- 📌 Рекомендуется запускать бэкапы в периоды низкой нагрузки (ночью)
- 📌 pg_dump создает согласованный снимок БД без блокировки

### Хранение

- 💾 Размер бэкапа зависит от объема данных (обычно 50-200 МБ)
- 💾 При `KEEP_AUTO_BACKUPS=7` будет храниться ~7 бэкапов (~500-1400 МБ)
- 💾 Убедитесь, что достаточно дискового пространства

## 🔍 Мониторинг

### Проверка работы

1. Убедитесь, что бэкапы создаются:
   ```bash
   ls -lh backups/auto/
   ```

2. Проверьте логи приложения:
   ```bash
   grep "Автоматический бэкап" logs/app.log
   ```

3. Проверьте размер и дату последнего бэкапа:
   ```bash
   ls -lth backups/auto/ | head -5
   ```

## 🛠️ Восстановление из автоматического бэкапа

Для восстановления используйте `pg_restore`:

```bash
# Список содержимого бэкапа
pg_restore -l backups/auto/auto_backup_20250121_020000.dump

# Восстановление (ВНИМАНИЕ: удалит текущие данные!)
pg_restore -h localhost -U postgres -d your_database --clean --if-exists backups/auto/auto_backup_20250121_020000.dump
```

Или через интерфейс управления версиями (если бэкап был сохранен как версия).

## 🚨 Устранение неполадок

### Бэкапы не создаются

1. Проверьте, что `ENABLE_SCHEDULED_BACKUPS=True`
2. Проверьте логи на наличие ошибок
3. Убедитесь, что pg_dump доступен в PATH
4. Проверьте права доступа к директории `backups/auto/`

### Ошибки подключения к БД

- Проверьте переменные окружения (`DB_HOST`, `DB_USER`, etc.)
- Убедитесь, что пароль БД правильный (`DB_PASS`)
- Проверьте доступность PostgreSQL

### Ошибки дискового пространства

- Уменьшите `KEEP_AUTO_BACKUPS`
- Переместите `AUTO_BACKUP_DIR` на другой диск
- Настройте внешнее хранилище для бэкапов

## 📈 Расширенная конфигурация

Для более гибкой настройки можно изменить `scheduled_backup_service.py`:

### Несколько бэкапов в день

```python
# В config.py
BACKUP_SCHEDULE = {
    'hour': '*/6',  # Каждые 6 часов
    'minute': 0
}
```

### Разные расписания для разных дней

```python
# В config.py
BACKUP_SCHEDULE = {
    'day_of_week': 'mon-fri',  # Только будни
    'hour': 2,
    'minute': 0
}
```

### Бэкапы определенных схем

Измените команду pg_dump в `scheduled_backup_service.py`:

```python
cmd = [
    pg_dump_path,
    "-h", db_host,
    "-p", db_port,
    "-U", db_user,
    "-F", "c",
    "-n", "generation",  # Только схема generation
    "-n", "refdata",     # и refdata
    "-f", backup_file,
    db_name
]
```

## 📝 Пример конфигурации Production

На сервере Astra бэкапы делаются **systemd timer** (`generation-app-backup.timer`) и скриптом
`/opt/generation-app/app/scripts/backup_pg.sh`. Дампы лежат в `/var/backups/generation-app/`,
а не в каталоге приложения (и не в `.deb`). Подробнее: `docs/deployment/ASTRA_INSTALL.md`, раздел 5.

```bash
# /etc/generation-app/app.env
BACKUP_BASE_DIR=/var/backups/generation-app
AUTO_BACKUP_DIR=/var/backups/generation-app/auto
KEEP_AUTO_BACKUPS=14
ENABLE_SCHEDULED_BACKUPS=False
```

Встроенный APScheduler (`ENABLE_SCHEDULED_BACKUPS=True`) оставляйте для локальной разработки
или если timer недоступен.
