# Руководство по миграции на новую систему конфигурации

## Что изменилось

### ✅ Улучшения безопасности:

1. **Убран хардкод SECRET_KEY** - теперь обязателен в `.env`
2. **Раздельные конфиги** для Development и Production
3. **Автоматическая проверка** обязательных параметров
4. **DEBUG выключен по умолчанию** в production

### 📝 Структура конфигов:

- `Config` - базовый класс
- `DevelopmentConfig` - для разработки (DEBUG=True)
- `ProductionConfig` - для production (DEBUG=False, строгие настройки)
- `TestingConfig` - для тестирования

## Что нужно сделать

### 1. Создайте файл `.env`

```bash
cp .env.example .env
```

### 2. Настройте обязательные параметры

Откройте `.env` и установите:

```env
# Сгенерируйте новый ключ:
# python -c "import secrets; print(secrets.token_hex(32))"
SECRET_KEY=ваш-новый-секретный-ключ

# Параметры БД
DB_USER=ваш_пользователь
DB_PASSWORD=ваш_пароль
DB_HOST=localhost
DB_NAME=ваша_база
```

### 3. Установите режим работы

Для разработки:
```env
FLASK_ENV=development
```

Для production:
```env
FLASK_ENV=production
```

### 4. Проверьте работу

Запустите приложение:
```bash
python run.py
```

Если все настроено правильно, приложение запустится. Если нет - увидите понятное сообщение об ошибке.

## Важные изменения

### ⚠️ Старые переменные:

- `DEBUG=True/False` → теперь используйте `FLASK_ENV=development/production`
- Хардкод `SECRET_KEY` → теперь обязателен в `.env`

### 🔒 Безопасность:

- В production автоматически:
  - `DEBUG=False`
  - `SESSION_COOKIE_SECURE=True` (требует HTTPS)
  - `WTF_CSRF_SSL_STRICT=True`

## Проверка

После настройки проверьте:

1. ✅ Приложение запускается без ошибок
2. ✅ В development режиме работает автоперезагрузка
3. ✅ В production режиме DEBUG выключен
4. ✅ Все формы работают (CSRF защита активна)

## Помощь

Если возникли проблемы:

1. Проверьте наличие всех обязательных переменных в `.env`
2. Убедитесь, что `.env` находится в корне проекта
3. Проверьте логи приложения на наличие ошибок
4. См. подробную документацию: `docs/CONFIGURATION.md`
