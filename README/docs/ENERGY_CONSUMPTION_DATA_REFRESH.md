# Обновление данных модуля «Спрос»

На всех 40 HTML-маршрутах блюпринта `energy_consumption_bp` показана кнопка **«Обновить данные»**: на главной странице, списках территорий и энергосистем, страницах ввода, сводках, сводных таблицах, страницах заряда ГАЭС и текстов формул. На JSON API, импорте, экспорте Excel и в других модулях кнопка не добавляется. Отдельный модуль долгосрочного прогноза потребления не меняется.

## Поведение

- По умолчанию кнопка желтая. На страницах с округлением она находится в той же строке непосредственно слева от всей группы «Округл» (перед настройками темпов прироста и общих значений). На страницах без округления сохраняется отдельная панель над содержимым.
- Каждые 20 секунд, при возвращении на вкладку и получении фокуса браузер проверяет версию исходных данных.
- Если версия изменилась, кнопка становится красной с текстом **«Имеются изменения, обновить данные?»**. Открытая таблица сама не перезагружается.
- Успешное автосохранение в сводке ОЭС не делает кнопку красной в той же вкладке: ответ сохранения подтверждает собственные изменения. Другие вкладки продолжают получать уведомления. Если до сохранения или между его commit были чужие изменения, предупреждение сохраняется. Запоздавший ответ проверки, начатой до автосохранения, не меняет индикатор.
- Нажатие сбрасывает существующие кеши отображения Спроса и перезагружает текущую страницу. Фильтры в URL, округление и фрагмент адреса сохраняются.
- При обнаружении введенных значений в таблице сначала запрашивается подтверждение. Отмена не очищает кеш и не перезагружает страницу.
- Если во время запроса обновления появились новые правки, перезагрузка отменяется.
- При ошибке обновления таблица и красное состояние кнопки сохраняются; рядом показывается сообщение об ошибке.

## Что изменилось

Первый этап истории причин для Спроса, Нагрузок и Энергобалансов описан в [DATA_REFRESH_HISTORY.md](DATA_REFRESH_HISTORY.md). Он добавляет время загрузки страницы и диалог событий, не заменяя счетчик актуальности. Перед запуском новой версии требуется миграция `gs26110301`.

## Версия данных и кеш

`ec:data_revision` – отдельный счетчик сохраненных исходных данных в общем Redis. Он не связан с поколением кеша JSON-сводок `ec_summary:cache_gen:v8`. Простое чтение страницы или нажатие «Обновить данные» в другой вкладке не меняет версию данных и не делает кнопку красной.

Обработчик SQLAlchemy публикует изменения только после успешного commit внешней транзакции. Обычные изменения ORM и массовые ORM insert/update/delete учитываются; rollback, неудачный commit и присваивание прежнего значения не публикуются. Записи журнала посещений не являются источниками Спроса.

Отслеживаются модели Спроса, генерации (в том числе заряд ГАЭС), справочников и территорий. Счетчик общий для страниц и версий БД: изменения в связанном источнике могут уведомить несколько открытых страниц, даже если не затрагивают их текущий фильтр. Версия БД включена в токен проверки. Перед публикацией новой версии инвалидируется серверный кеш сводок; штатные пути сохранения и импорта также сохраняют существующий полный сброс связанных кешей.

Без доступного Redis используется локальный счетчик процесса. Для уведомлений между несколькими процессами приложения нужен общий Redis. HTML-страницы, JSON-данные сводок и ответы служебного API отдаются с `Cache-Control: no-store, private`, чтобы после обновления браузер не подставлял старый JSON вместо актуальной серверной сводки.

## API и повторное использование

- `GET /energy_consumption/data-revision/` – текущий токен вида `7:data:12`.
- `POST /energy_consumption/refresh-data/` – сброс кешей отображения без изменения исходных данных и их версии. Нужны вход в систему и CSRF-токен; право редактирования не требуется.

Используются общие шаблон `common/_data_refresh.html`, обработчик транзакций `DataChangeTracker` и существующий JS `js/energy_balance/data_refresh.js`. DOM-идентификаторы с префиксом `energyBalance` сохранены для совместимости с энергобалансами. На каждой странице размещается только одна панель.

После установки изменений нужно перезапустить приложение и заново открыть страницы.

## Проверки

- `tests/energy_consumption/test_consumption_data_refresh.py` – все HTML-маршруты, настоящий шаблон главной страницы, API, авторизация/CSRF, commit, массовые операции, rollback, Redis и независимость версии от очистки кеша.
- `tests/energy_consumption/test_consumption_data_refresh_browser.py` – Chrome: уведомление после commit, сохранение введенных значений при отмене, обновление таблицы, вторая вкладка, цвета и ошибки обновления.
- Существующие тесты энергобалансов проверяют совместимость общего шаблона и обработчика транзакций.
