# Перенос связей оборудования между версиями БД

Операция доступна администратору по ссылке из словаря станций и групп оборудования.
Интерфейс открывается отдельной страницей в новой вкладке, без модального окна.
Версии загружаются при открытии страницы. После переноса можно открыть таблицу
или обновить исходную вкладку словаря.
Перед записью формируется предварительный план. В БД записываются только выбранные строки.

## Переход из проверки external_code

В таблице `/generation/stations/external_code_check` у группы с пропусками в именованных
версиях доступны ссылки «Перенести группу и связи в ...». Ссылка открывает эту же
страницу переноса, задает исходную группу, версию-источник и целевую версию, а также
включает опцию создания отсутствующих групп. Анализ и запись автоматически не запускаются.

План ограничивается выбранной группой, ее связями со станциями и типами, явными
привязками агрегатов и типами связанных агрегатов. Если у агрегата явно указана другая
группа, его тип не попадает в такой план только на основании общей станции и типа.
Необходимые родительские группы создаются по прежним правилам.

Целевую именованную версию можно выбрать на странице без переключения текущей
версии приложения. Выбранная цель и исходная группа входят в подписанный план:
изменение полей запроса при применении не меняет его область действия.
После выполнения кнопка «Перенести в следующую версию» позволяет выбрать новую
цель, повторить анализ и подтвердить новый план. Заполнение всех версий выполняется
последовательно, с отдельным подтверждением для каждой цели, а не одной общей транзакцией.
Столбец «Без версии» не является целевой версией и не заполняется.
Запрет `database_version_id = NULL` действует и в HTTP API, и при прямом вызове
сервиса: до загрузки снимка, построения плана и записи проверяются положительные
целочисленные ID двух различных версий. Исходные записи выбираются строго в
версии-источнике, соответствия – строго в целевой версии. Совпадающие коды записей
без версии или из третьей версии не используются как запасное соответствие.
Топливная запись с неправильной версией блокирует перенос привязки, а не получает
новую версию. SQL-обновления агрегатов и топливных записей дополнительно ограничены
`database_version_id` целевой версии.
После переноса обновите таблицу проверки, чтобы увидеть фактические записи и коды.

## Идентификаторы

| Сущность | Устойчивый идентификатор |
| --- | --- |
| Агрегат `Machine` | `external_code` |
| Станция `Station` | `external_code` |
| Тип группы `EquipmentGroupType` | `ref_uuid` |
| Итоговая группа `EquipmentGroup` | `external_code` |

Внутренние `id` различаются между версиями. При записи используются ID целевой версии.
Названия и номера групп не заменяют устойчивые идентификаторы.
Пустые, отсутствующие и неоднозначные соответствия не подбираются автоматически.

## Независимые строки плана

### Тип агрегата (`type:<ID исходного агрегата>`)

Агрегат сопоставляется по `external_code`, тип – по `ref_uuid`.

- Совпадающий тип не меняется.
- Пустой тип цели заполняется.
- Отличающийся тип цели заменяется исходным; строка выбрана автоматически.
- Пустой тип источника не очищает тип цели и не формирует строку изменения типа.

Перенос типа не зависит от наличия станции, итоговой группы, связей группы
или записи `MachineFuelParam`. Он не создает топливную запись и не меняет ее поля.

### Связь станции с типом (`station_link:<ID исходной связи>`)

Находится или создается `EquipmentGroupSetStation` для целевых станции, типа и версии.
Строка переносится и без агрегатов или итоговых групп.
Пустой тип исходной связи сохраняется как пустой тип оболочки составной станции;
отсутствующее соответствие непустому типу не считается оболочкой.
Связь без станции и дубликаты пары станции с типом блокируются.

### Связь итоговой группы (`link:<ID исходного EquipmentGroupSet>`)

Итоговая группа сопоставляется по `external_code`.
Добавляется отсутствующая пара `EquipmentGroupSet` между целевой группой
и целевой связью станции с типом.

Существующие связи не удаляются, включая связи с другими типами и итоговыми группами.
Поддерживается несколько итоговых групп у одной пары станции и типа,
а также несколько станций у одной итоговой группы.
Наличие агрегатов без явной итоговой группы не блокирует добавление связей.

### Явная итоговая группа агрегата (`machine:<ID исходного агрегата>`)

Переносится только явно заданная `MachineFuelParam.equipment_group_id` источника.
В целевой топливной записи устанавливаются целевой ID группы и ее служебный код `numb1120`.
Отсутствующая целевая топливная запись создается без копирования прочих параметров источника.

Если явной привязки в источнике нет, она не вычисляется по станции и типу.
Существующая явная привязка цели в этом случае не очищается.
Замены явной или вычисляемой итоговой группы требуют выбора строки вручную.
Тип агрегата меняется только отдельной строкой типа, а не вместе с явной группой.

## Создание итоговых групп

Существующая группа используется без перезаписи ее параметров, номера или структуры.
Отсутствующая создается только при включенной опции создания групп.
Создаются только группы выбранных строк и необходимые родительские группы.
Ссылки на справочники разрешаются в целевой версии; годовые параметры не копируются.
Коллизии номеров и некорректная структура создаваемой составной станции блокируют создание.
Отсутствие итоговой группы не блокирует независимый перенос типа или связи станции с типом.

## Безопасность и повторный запуск

Источник, годовые параметры и результаты расчетов не изменяются.
Замена типа агрегата не удаляет старые связи станций и итоговых групп.
Повторный анализ после успешного переноса показывает совпадения и не предлагает дубликаты.

План подписан, не имеет ограничения по времени и проверяется повторно перед записью.
Изменение снимка данных отменяет применение старого плана.
Запись и журнал выполняются одной транзакцией. При ошибке изменения откатываются.
Отчет Excel сохраняет весь показанный снимок плана независимо от фильтра и страницы.
