# Актуальность данных энергобалансов

На табличных страницах модуля «Балансы электрической энергии и мощности» доступны:

- желтая кнопка «Обновить данные», расположенная непосредственно слева от «Округл» в той же строке, если на странице есть настройка округления;
- при обнаружении новых данных кнопка становится красной с текстом «Имеются изменения, обновить данные?»;
- проверка актуальности каждые 20 секунд и при возврате во вкладку;
- подтверждение обновления, если в таблице есть введенные значения или ошибки сохранения.

Поддержаны балансы ЭЭ и мощности, прогноз ТЭС, страницы выработки по типам станций, общая выработка и ее итоговые суммы, перетоки, импорт/экспорт и прием/отдача между ОЭС. На хабе, экспортных файлах и в других модулях панель не выводится.

## Автоматическая инвалидация

Обработчики SQLAlchemy отслеживают изменения моделей энергобалансов и их источников: генерации, перспективных площадок, потребления, максимумов мощности, топливных групп, территорий и справочников. После успешного commit сбрасывается существующий кеш энергобалансов и изменяется отдельный счетчик сохраненных исходных данных (`eb:data_revision`). Счетчик поколения кеша (`eb:cache_generation`) используется только для ключей кеша: обычная очистка кеша не публикует уведомление об изменении данных. Чтение и запись журналов, откат и неуспешный commit не публикуют обновление. Поддержаны ORM bulk INSERT/UPDATE/DELETE через `Session.execute` и вложенные транзакции; commit savepoint не публикует изменения до commit внешней транзакции.

Установленная мощность также использует кеш агрегаций станций. Для запросов из энергобалансов в ключ агрегации включен счетчик поколения энергобалансов. Поэтому обновление не возвращает старые мощности из этого дополнительного слоя кеша и не требует очистки кешированных страниц остальных модулей. Результат начатого до сохранения расчета записывается под старым ключом и не подменяет новое поколение.

Ручное обновление очищает только кеш энергобалансов, затем повторно открывает текущую страницу с теми же параметрами URL. Само нажатие «Обновить данные» не делает кнопку красной в других вкладках или у других пользователей. Общая команда очистки всех кешей приложения не вызывается. Существующая схема кеша общая для листов и версий БД, поэтому уведомление консервативное: оно может появиться при изменении другого связанного листа или версии. Версия БД также входит в токен страницы, чтобы смена версии в другой вкладке не осталась незамеченной.

## Защита редактирования

Уведомление само не перезагружает страницу и не заменяет ячейки. Если значения отличаются от значений при открытии страницы, ручное обновление требует подтверждения. Проверка намеренно консервативная: после автосохранения подтверждение тоже возможно. Зеленый цвет ячейки не считается гарантией отсутствия новых правок.

Если во время запроса обновления введены новые значения, перезагрузка отменяется и показывается сообщение. При ошибке сети или сервера введенные значения остаются на странице, кнопку можно нажать повторно. При подтверждении пользователь соглашается на повторную загрузку таблицы; перед этим нужно завершить сохранение. Отдельного механизма разрешения конфликтов одновременного редактирования одной и той же ячейки этим изменением не добавляется.

## API и эксплуатация

- `GET /energy_balance/data-revision/` – версия сохраненных исходных данных и версия БД, без изменения данных.
- `POST /energy_balance/refresh-data/` – сброс кеша энергобалансов, без изменения данных БД.

Оба маршрута требуют авторизации. POST защищен CSRF и доступен пользователям с правом чтения: он не дает права изменять исходные данные. Таблицы и ответы API имеют `Cache-Control: no-store, private`.

Для обмена уведомлениями между несколькими процессами нужен работающий общий Redis, как и для существующего распределенного кеша. Без Redis действует существующий локальный fallback, который не обеспечивает обмен состоянием между процессами. Прямые SQL-изменения вне приложения и сторонние импорты без этих обработчиков автоматически не обнаруживаются; после них следует использовать «Обновить данные».

После установки изменений требуется перезапуск приложения, миграция БД не нужна.
