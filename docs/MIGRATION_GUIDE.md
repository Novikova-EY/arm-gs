# Руководство по работе с миграциями

## Текущая ситуация

Создана новая полная миграция `1a209997491c_initial_full_schema.py`, которая создает:
- Индексы
- Внешние ключи (foreign keys)
- Уникальные ограничения (unique constraints)

**ВАЖНО:** Эта миграция НЕ создает таблицы. Таблицы должны уже существовать в базе данных.

## Сценарии применения

### 1. Существующая база данных (development/production)

Если у вас уже есть база данных с таблицами и данными:

**Вариант А:** Если индексы и ключи уже существуют
```bash
flask db stamp head
```
Эта команда пометит миграцию как примененную без выполнения операций.

**Вариант Б:** Если индексы и ключи отсутствуют
```bash
flask db upgrade
```
Миграция применится нормально и создаст все необходимые индексы и ключи.

### 2. Новая пустая база данных

Если база данных пустая (нет таблиц):

1. Сначала создайте таблицы:
```python
from app import create_app, db
app = create_app()
with app.app_context():
    db.create_all()
```

2. Затем примените миграцию:
```bash
flask db upgrade
```

### 3. Будущие миграции

Все новые миграции будут нормально применяться в development, так как они будут иметь правильную цепочку зависимостей:

```bash
# Создание новой миграции
flask db revision --autogenerate -m "описание изменений"

# Применение миграции
flask db upgrade
```

Новые миграции автоматически будут ссылаться на `1a209997491c` как на `down_revision` и применятся последовательно.

## Проверка состояния миграций

Проверить текущее состояние миграций:
```bash
flask db current
flask db history
```

## Откат миграции

Если нужно откатить миграцию:
```bash
flask db downgrade -1
```

## Рекомендации для development

1. **Если база данных уже существует** - используйте `flask db stamp head` для пометки миграции как примененной
2. **Если создаете новую базу** - сначала `db.create_all()`, затем `flask db upgrade`
3. **Для новых изменений** - просто создавайте новые миграции через `flask db revision --autogenerate`

## Рекомендации для production

1. Всегда делайте бэкап базы данных перед применением миграций
2. Проверяйте миграции на тестовой среде перед production
3. Используйте `flask db upgrade` для применения миграций
