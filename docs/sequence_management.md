# Управление последовательностями PostgreSQL

## Описание проблемы

При создании новых записей (станций, агрегатов и т.д.) может возникать ошибка:
```
ОШИБКА: повторяющееся значение ключа нарушает ограничение уникальности "..._pkey"
DETAIL: Ключ "(id)=(N)" уже существует.
```

Это происходит когда последовательность (sequence) для автоинкремента ID не синхронизирована с текущими данными в таблице. Обычно это случается после импорта данных с явным указанием ID.

## Автоматическое исправление

С версии системы, содержащей данное исправление, **сервис создания станций автоматически исправляет последовательность** при возникновении такой ошибки и повторяет попытку создания записи.

## Ручное управление последовательностями

### Проверка всех последовательностей

```bash
python manage_sequences.py check
```

Выводит список всех последовательностей и их статус:
- **OK** - последовательность в порядке
- **ТРЕБУЕТСЯ ИСПРАВЛЕНИЕ** - последовательность нуждается в обновлении

### Проверка конкретной таблицы

```bash
python manage_sequences.py check stations
```

### Исправление всех последовательностей

```bash
python manage_sequences.py fix
```

Автоматически исправляет все последовательности, которые нуждаются в исправлении.

### Исправление конкретной таблицы

```bash
python manage_sequences.py fix stations
```

## Технические детали

### Файлы

- `app/common/services/sequence_repair_service.py` - основной сервис для работы с последовательностями
- `app/common/services/tranzaction_services.py` - содержит функцию `quick_fix_seq()`
- `manage_sequences.py` - CLI утилита для управления последовательностями

### Функции в коде

```python
from app.common.services.tranzaction_services import quick_fix_seq
from config import SCHEMA_GENERATION

# Исправить последовательность для таблицы
quick_fix_seq(SCHEMA_GENERATION, "stations", "id")
```

### Обработка ошибок

Функция `add_station_service` автоматически обрабатывает ошибку `UniqueViolation` на первичном ключе:

1. При возникновении ошибки `psycopg2.errors.UniqueViolation` на `stations_pkey`
2. Автоматически вызывается `quick_fix_seq()` для исправления последовательности
3. Повторяется попытка создания записи
4. Если проблема не решена, выбрасывается исходная ошибка

## Рекомендации

1. **После импорта данных** - всегда запускайте `python manage_sequences.py fix` для исправления всех последовательностей
2. **При появлении ошибки** - система должна автоматически исправить проблему, но можно запустить исправление вручную для конкретной таблицы
3. **Профилактика** - периодически запускайте `python manage_sequences.py check` для проверки состояния последовательностей
