# Управление кэшем Redis

## Описание проблемы

При работе с системой может возникнуть ситуация, когда кэш Redis содержит устаревшие данные. Например, в кэше может быть сохранен список из 4849 станций, хотя в базе данных уже только 2424 станции.

## Способы очистки кэша

### 1. Через веб-интерфейс (рекомендуется)

На странице "Электростанции" добавлены кнопки управления кэшем:

- **🗑️ Очистить кэш** - полностью очищает кэш станций
- **🔄 Обновить кэш** - принудительно обновляет кэш с актуальными данными

**Как использовать:**
1. Откройте страницу со списком станций
2. Нажмите кнопку "🗑️ Очистить кэш" для полной очистки
3. Или нажмите "🔄 Обновить кэш" для обновления с актуальными данными
4. Страница автоматически перезагрузится после операции

### 2. Через командную строку

Используйте скрипт `scripts/clear_cache.py`:

```bash
# Показать информацию о кэше
python scripts/clear_cache.py info

# Очистить только кэш станций
python scripts/clear_cache.py stations

# Очистить весь кэш Redis
python scripts/clear_cache.py all
```

### 3. Прямое подключение к Redis

Если нужно более детальное управление:

```bash
# Подключиться к Redis контейнеру
docker exec -it redis redis-cli

# Посмотреть все ключи кэша станций
KEYS stations:*

# Удалить конкретный ключ
DEL stations:sorted:v41:d5ebc01381ae57e48520557548902b6d

# Очистить всю базу данных
FLUSHDB
```

## Когда нужно очищать кэш

Очистка кэша необходима в следующих случаях:

1. **После массового удаления данных** - когда количество записей в БД значительно изменилось
2. **После импорта новых данных** - когда добавлены новые станции или машины
3. **При ошибках отображения** - когда данные на странице не соответствуют реальности
4. **После обновления структуры данных** - когда изменились модели или связи

## Автоматическое управление кэшем

Система автоматически управляет кэшем:

- **TTL (время жизни)**: 30 минут
- **Автообновление**: каждые 25 минут в фоновом режиме
- **Fallback**: если Redis недоступен, используется in-memory кэш

## Мониторинг состояния кэша

### Проверка через скрипт
```bash
python scripts/clear_cache.py info
```

### Проверка через Docker
```bash
# Статус Redis контейнера
docker ps | grep redis

# Подключение к Redis
docker exec redis redis-cli ping

# Количество ключей
docker exec redis redis-cli dbsize
```

## Устранение проблем

### Redis недоступен
```bash
# Перезапуск Redis контейнера
docker restart redis

# Проверка логов
docker logs redis
```

### DetachedInstanceError после очистки кэша
Эта ошибка возникает, когда объекты SQLAlchemy становятся "отсоединенными" от сессии после очистки кэша.

**Решение:**
```bash
# Очистить все кэши (Redis + LRU)
python scripts/clear_lru_caches.py all
```

**Или через веб-интерфейс:**
- Используйте кнопку "🔄 Обновить кэш" вместо "🗑️ Очистить кэш"
- Система автоматически очистит все связанные кэши

### Кэш не обновляется
1. Проверьте подключение к Redis
2. Очистите кэш вручную
3. Перезапустите приложение

### Медленная работа после очистки
Это нормально - система пересоздает кэш при первом обращении к данным.

## Логирование

Все операции с кэшем логируются в консоль приложения:
- `[SORTED CACHE HIT REDIS]` - использование кэша
- `[CACHE MISS]` - кэш не найден, данные загружены из БД
- `[🗑 CACHE CLEARED REDIS]` - кэш очищен
- `[CACHE WARMUP]` - прогрев кэша

## Рекомендации

1. **Регулярно мониторьте** состояние кэша через веб-интерфейс
2. **Очищайте кэш** после значительных изменений в данных
3. **Используйте веб-интерфейс** для обычных операций
4. **Используйте скрипт** для диагностики и массовых операций
5. **Не очищайте весь кэш** без необходимости - это замедлит работу системы
